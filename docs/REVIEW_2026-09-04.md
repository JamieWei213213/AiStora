## Bugs found (each confirmed by reading the code or reproducing)

### Must fix before public launch

1. **Login memory-exhaustion DoS** — `routes/auth.py:100-108`, `services/rate_limit.py`. The raw email string from the JSON body (up to the 50 MB request cap) becomes a rate-limiter key; keys are never evicted. One client can OOM a 1 GB task in about a minute. Fix: validate/truncate the email (≤120 chars) *before* throttling and drop empty deques.
2. **Unbounded LLM cost per request** — `routes/data.py`, `services/privacy.py`. No cap on column count or column-name length; every column name is sent to Gemini on every turn (up to 8 turns × 20 requests/min). A registered user can upload a 5,000-column header and burn your key. Fix: reject >200 columns or names >64 chars at upload; add a per-user daily token budget.
3. **Rate limits are per-process** — every limiter is in-memory. With 2 gunicorn workers all limits are ×2, and ×N tasks. Move the sliding window into Redis (you already have the client).
4. **413 returns HTML** — no `@app.errorhandler(413)`; the UI calls `response.json()` and shows a generic "File upload failed". Reproduced with a 52 MB upload. Add a JSON 413 handler and a client-side size check.
5. **Parser silently truncates** — `engine/parser.py:131,164`. `csv.Error` (e.g. a field >128 KB) is `print`ed and parsing just stops, so the upload "succeeds" with fewer rows. Raise instead. Also `UnicodeDecodeError` is not caught: a Latin-1 CSV (common from Excel) returns a 500 with a codec message (reproduced). Try `utf-8-sig` then `cp1252`.
6. **`inf` in a float column breaks JSON** — `engine/parser.py:100`, `routes/chat.py:71`. `jsonify` emits bare `Infinity`, which `JSON.parse` in the browser rejects. Map non-finite floats to `null`.
7. **Chart flow leaks group labels to quickchart.io** — `services/agent_tools.py:698-718`. Raw rows never leave the server (verified), but group-by *values* (e.g. customer names or emails) go into a third-party GET URL. Refuse charts on non-"ordinary" columns, or render with Chart.js locally and drop QuickChart.

### Should fix

8. **Session ID not rotated on login** — `routes/auth.py:122`. Flask-Session's `clear()` keeps `session.sid`; the comment claims fixation protection that isn't there. Set `session.sid = secrets.token_urlsafe(32)` after clearing.
9. **CSP blocks the inline script in `templates/base.html:36-43`** — `script-src` has no `'unsafe-inline'`/nonce. On the landing page (no `scripts.js`) every lucide icon renders empty. Move `lucide.createIcons()` into a static file.
10. **Tailwind Play CDN + `lucide@latest` in production** — unpinned, no SRI, both hosts trusted by CSP. Build Tailwind at deploy time, vendor a pinned lucide, tighten `script-src` to `'self'`.
11. **Ephemeral disk grows forever** — S3 materialise cache (`/tmp/aistora-cache`) is never evicted; the JSONL audit log in `/tmp` is unrotated and lost on restart, so it isn't an audit trail. LRU-evict the cache; ship audit lines to CloudWatch via the logger.
12. **Model routing sends trivial questions to the expensive model** — `services/request_router.py`. "How many rows are in sales?" classifies as `general`, and with >1 table that routes to `gemini-3.6-flash` (5–6× the price). Add "how many"/"number of" to the aggregation words. "over" as a comparison word also pushes "sales over $100" to advanced.
13. **Prompt injection via column headers** — headers reach the model unmodified in the default `classified` mode. Tools are constrained so impact is limited to misleading answers, but sanitise names to `[A-Za-z0-9_ ]{1,64}` at upload.
14. **Capacity** — 2 workers × 2 threads = 4 concurrent requests per task while a chat can hold a thread 45 s+; four slow requests starve `/health` and ECS kills the task mid-run. Raise threads (I/O-bound) and set `health_check_grace_period_seconds`.
15. **UI** — Enter doesn't submit the login form (no `<form>`); switching databases leaves the previous DB's relationship list on screen; rename/delete calls have no try/catch or loading state; chat header clips on phones (~375 px).
16. **Repo hygiene** — your personal resume `.tex` and your AWS account ID are in a public repo. The README says `test_agent_ui.py` needs Chrome; it doesn't (it's a plain template test), so `selenium`/`webdriver-manager` in `requirements-dev.txt` are dead weight.

## What is done well

Authorization is consistent (every project/table/run lookup filters by `session['user_id']`); the "schema only" boundary to the LLM actually holds (tool results are counts/columns/names, filter values are stripped from the audit log); production refuses to start without `SECRET_KEY` or with an unreachable Redis; cookies are Secure/HttpOnly/Lax with CSP + HSTS; every row loop checks cancellation and hard caps; Alembic owns the schema; CI builds and health-checks the container before deploying via OIDC. Frontend escaping is thorough.

### Cheapest setups that still let you say "AWS" honestly

**Option A — one EC2 instance, ~$10–14/month (recommended).**
`t4g.small` (2 vCPU, 2 GB, ARM, ≈$12 on-demand, ≈$7 with a 1-year no-upfront savings plan) in a public subnet, running your existing `docker-compose.yml` (app + Postgres + Redis) with Caddy in front for automatic HTTPS. Keep the S3 dataset backend (real S3, ~$0.10), an IAM instance role scoped to the bucket, secrets in SSM Parameter Store (free) instead of Secrets Manager, CloudWatch agent for logs, and deploy from GitHub Actions via OIDC + `aws ssm send-command` (or ECR pull). Nightly `pg_dump` to S3 via cron. You still get to talk about EC2, S3, IAM least privilege, SSM, CloudWatch, OIDC CI/CD and Terraform — and this is the architecture almost every real small SaaS starts with. No ALB, no NAT, no RDS, no ElastiCache.

**Option B — keep ECS/Fargate but strip the expensive parts, ~$45–50/month.**
Delete the NAT gateway (put the task in a public subnet with `assign_public_ip = true`; the security group still only admits the ALB), keep the ALB and RDS, run Fargate Spot on ARM (Graviton) for ~$5 instead of $18, disable Container Insights, keep `enable_elasticache = false` while `desired_count = 1`. You keep the "ECS/Fargate + RDS + ALB" resume line.

**Option C — keep exactly what you have, but only when you need it, ~$0–2/month idle.**
`terraform destroy` when not demoing, `terraform apply` + one CI run (~15–20 min) before an interview. S3 buckets and Terraform state survive. This is what you effectively did in August.

A `db.t4g.micro` RDS instance and an ALB alone are ≈$30/month, so any design that keeps both can't get under that. If "as cheap as possible" is the priority, Option A is the answer; if the Fargate line on the resume matters more, Option B.
